# 심슨 히트 앤 런 (GC) — 「한글을 넣으면 □ / 게임 로딩에서 크래시」의 근본 해결

세션 2026-09-11. 오래 막혀 있던 **부팅 공유 페이지·프런트엔드 한글화**를 풀었다.

## 1. ★★★ 정적 폰트 참조는 «실제로 어느 폰트로 그려지는지»를 말해 주지 않는다

`Sound.pag` 는 `frontend.p3d` 안에 있고, 폰트 참조 청크(`0x00018104`)에도 `boulderK16`
(한글 863자)이라고 적혀 있다. 그런데 **실기에서는 전부 □** 였다.

RAM 실측(메인 메뉴에서 폰트 객체를 전수로 세어 봄, vtable `0x8039C474`) —

```
0x808935F8 boulderB16    141 (한글 5)    참조   5곳   backend.p3d
0x80A259D0 boulder_16    136 (한글 0)    참조 121곳   bootup.p3d   ★
0x80A3DC68 swz721n_10    136             참조   1곳
0x80A3DFC0 Tt2001m__14   136 (한글 0)    참조   1곳   frontend.p3d
0x80A3E318 boulder_24    136             참조   1곳
0x80A3E670 swz721mi_12   136             참조   1곳
0x80A3E9C8 boulderK16   1006 (한글 863)  참조  61곳   frontend.p3d
0x80A443A8 Tt2001m__14   136 (한글 0)    참조  96곳   bootup.p3d   ★
```

**UI 대부분(121+96 = 217곳)이 bootup.p3d 의 영문 폰트 객체에 묶여 있었다.**
한글 폰트는 61곳뿐. 그래서 화면마다 한글/□ 가 갈렸다
(같은 메인 메뉴에서 `게임 계속하기`는 한글, 아래 `확인` 버튼은 □).

> 지난 세션의 「사운드 페이지는 정적으로 863자 폰트를 가리키는데도 실기 □ — 원인 미규명」이 이것이다.
> ⛔ `scratchpad/fontscan.py` 같은 «정적 참조 검사»로 □ 를 판정하면 안 된다. RAM 을 읽어야 한다.

### 어느 폰트인지 가르는 법 (실측 절차)

1. 돌핀에서 문제 화면까지 간다.
2. MEM1 에서 vtable `0x8039C474` 를 찾아 폰트 객체를 전수로 센다.
3. 그 객체의 **꼬리 6워드**(`+0x2C`~`+0x40`)를 한글 폰트 것으로 덮어써 본다.
   화면이 한글로 바뀌면 그 객체가 범인이다.

## 2. 폰트 객체 구조 (실측 확정)

```
+0x00  vtable  0x8039C474
+0x08  이름 해시 1      +0x0C  이름 해시 2
+0x10  크기(f32)   +0x18 높이(f32)   +0x1C 베이스라인(f32)
+0x2C  텍스처 개수
+0x30  텍스처 배열
+0x34  ★ «못 찾은 글자에 쓸 대체 글리프 색인»(= U+7F7F □ 의 색인)
+0x38  글리프 개수
+0x3C  글리프 배열 (항목 40 B)
+0x40  코드 배열 (u16 × 개수, 오름차순)
```

이름 해시 쌍(실측) — `boulder_16` `A5C0BAC0/DDFB6C43` · `boulder_24` `A5C0BAC0/DDF86B8C` ·
`boulderK16` `A5C0BACC/E4042E57` · `boulderB16` `A5C0BAD5/E870B95A` ·
`Tt2001m__14` `5F611EFD/D229DA85`

`+0x34` 의 근거 —
```
8023DC14  bl 0x8023DCE8      글리프 색인 조회
8023DC18  cmpwi r3,0
8023DC20  lwz r3,0x34(r27)   ← 못 찾았을 때 이 색인을 쓴다
8023FA98  stw r5,0x34(r31)   로더가 코드 0x7F7F 를 만나면 그 색인을 적는다
```

## 3. ⛔ 꼬리를 그냥 공유하면 «이중 해제»로 죽는다

폰트 소멸자 `0x8023D5C4` 가 배열을 **직접 free** 한다.

```
8023D65C  lwz r3,0x30(r26) → bl 0x8006AA50   free(텍스처 배열)
8023D668  lwz r3,0x3C(r26) → bl 0x801A746C   글리프 배열 해제
8023D674  lwz r3,0x40(r26) → bl 0x8006AA50   free(코드 배열)
```

두 객체가 같은 배열을 가리킨 채 둘 다 소멸하면 힙이 깨진다.
**실측**: RAM 에서 꼬리만 바꿔 놓고 게임에 진입하자 로딩에서 크래시 —
```
PC(SRR0) 0x802289D0   LR 0x8023D598
boulderK16 0x80A3E9C8 : vtable 자리가 0x80B06D98 (프리리스트) ← 이미 해제됨
boulder_16 0x80A259D0 : codearr 여전히 0x80B30B98 ← 해제된 것을 가리킴
```

⇒ **소멸자 진입을 가로채 «손댄 객체면 원래 꼬리로 되돌린 뒤» 통과시켜야 한다.**
되돌렸을 때의 최악은 «그 순간만 영문» 이라 안전하다.

## 4. 해법 — `tools/fonthook.py` (파일 크기 증가 0)

한글 폰트를 **새로 올리지 않는다.** 이미 떠 있는 `boulderK16` 의 배열을 가리키기만 한다.
텍스처도 글리프표도 추가 0바이트 ⇒ 예전에 막혔던 **「bootup.p3d 를 키우면 크래시」를
아예 안 만난다.**

```
훅1  0x8023FA9C  or r3,r31,r31    폰트 적재 «완료» (에필로그 첫 명령, r31 = 폰트 객체)
     ⛔ 0x8023F740(코드배열 대입 직후)에 걸면 +0x34 가 아직 0 이다 — 로더가 0x8023FA98 에서 채운다
훅2  0x8023D5E4  lis r3,0x803A    폰트 소멸자 (LR 저장 뒤·널검사 뒤, r26 = 객체)
케이브 0x80003A88~0x80003D54  716 B 연속 0 (DOL·실기 RAM 둘 다 확인) — 144워드 576 B
자료   0x80004D88~0x80004E54  204 B
   +0x00 KF(살아 있는 한글 폰트) · +0x04 훅1횟수 · +0x08 훅2횟수 · +0x0C LR보관
   +0x14 부터 슬롯 4개(보폭 0x20) = 객체 · 패치됨표시 · 원래 꼬리 6워드
```
⛔ 둘 다 «함수 첫 명령»이 아니다 — 첫 명령을 가로채면 LR 이 저장되기 전이라 깨진다.
★ 두 자리 모두 «바로 앞이 `bl`» 이라 r0·r4~r12 가 전부 죽어 있다(자유롭게 쓸 수 있다).

**자막 케이브(`0x80004888~0x80004D1C`)와 겹치지 않는다.** `dolhook.py --reset` 도 여기까지
안 밀고, `fonthook.py --reset` 은 자기 것만 민다. 도구를 일부러 분리했다.

## 7. ⛔ 튜토리얼 상자는 «영문 확정» (2026-09-11 사용자 결정) — 그 근거

튜토리얼 상자(`Tutorial.pag`·`Hud.pag` 의 `TutorialMessage`)는 글자를 **스프라이트 그림**으로 찍는다.
한글을 넣으면 문자표(`0x8033D620`, 128칸)를 벗어나 음수 색인 → NULL 호출 → 크래시.

### ⛔ 「청크 종류만 폰트 텍스트 요소로 바꾸면 된다」는 **틀렸다** (실측 반증)

파일만 보면 바꿔치기가 될 것 같다 —
```
0x00018006 스프라이트 요소  data=661  pstr(이름)+u32×11+스프라이트 이름 80개
0x00018007 폰트 텍스트 요소 data=87~95 pstr(이름)+u32×10+pstr(폰트) + 자식 0x1800B(후보 키)
```
그런데 **실기 RAM 에서 두 객체의 구조가 아예 다르다.**
```
폰트 텍스트 요소 (DisableTutorial) 객체 0x80C824B4  vtbl 0x80397354
    +0x38 = 바이블 문자열을 «직접» 가리킨다
스프라이트 글자 요소 (TutorialMessage) 객체 0x80C82B70  vtbl 0x80396B3C
    +0xAC = «자기가 만든 문자열 객체»(0x802136F0 이 malloc(60) 해서 넣는다)
```
RTTI 로도 확인된다 — `Scrooby::Text` 와 `Scrooby::Sprite` 는 둘 다 `Scrooby::BoundedDrawable`
을 상속한 **형제**지 부모·자식이 아니다(이름표 `0x80366510` 부근).
게다가 글자를 그리는 `0x802133C8` 은 Scrooby 라이브러리가 아니라 **게임 HUD 코드**(0x8021xxxx)다.
HUD 가 그 요소를 Sprite 로 잡아 자기 setter 로 글을 넣으므로, 청크 종류만 바꾸면 형이 안 맞는다.

### ⭕ 그래도 «길»은 있다 (필요해지면 이렇게)

스프라이트 요소가 **지금 띄울 원문을 자기 안에 들고 있다**(`+0xAC` → 문자열 객체 → 버퍼).
자막 때와 같은 구도라 런타임에 「무엇을 띄우는지」를 읽을 수 있다.
```
① 0x802133C8(스프라이트 글자 그리기)을 훅으로 막아 영문 상자를 안 그리게 한다
② Tutorial.pag 의 폰트 텍스트 요소를 상자 자리로 «제자리» 이동 (PoC-E 와 같은 방법)
③ 케이브가 +0xAC 의 원문을 읽어 어느 TUTORIAL_* 인지 가리고, 한국어를 그 요소의 바이블 칸에 쓴다
```
가장 싼 첫 시험 = `DisableTutorial`(「튜토리얼 끄기」) 요소를 재활용해 상자 자리로 옮기기.
규모는 «자막 시스템의 축소판»(훅 1 + 케이브 + 바이블 칸 + 요소 이동)이다.

⇒ **사용자 결정: 안 한다. 튜토리얼 상자는 영문으로 둔다.**
   (`GO!`·`READY`·`MISSION FAILED!`·숫자 표시도 같은 스프라이트 방식이고 영문으로 자연스럽다.)

### 이번에 만든 조사 도구
`tools/ppcdis.py` — ISO 안 DOL 의 디스어셈블·xref·문자열 참조 찾기. 섹션별 델타를 헤더로 처리한다.
`tools/p3delem.py` — 요소 종류 훑기(`--list`). ⛔바꿔치기 기능은 위 이유로 **쓰지 말 것.**

## 8. ⛔⛔ 로딩 화면 폰트(`boulderB16`)는 케이브에 «넣으면 안 된다» (2026-09-11 실측)

로딩 화면 신문 헤드라인을 한글로 띄우려고 `HASH_EN` 에 `boulderB16`
(`0xA5C0BAD5` / `0xE870B95A`, `backend.p3d`)을 더하고 `NSLOT` 을 4→5 로 올렸다.
화면에는 한글이 잘 나왔지만 — **미션 중 불러오기에서 게임이 멈춘다.**

```
첫 화면에서 불러오기  → 정상
미션 진행 중 불러오기  → 멈춤          ← 사용자 신고로 갈라낸 결정적 증상
```

### 왜

`backend.p3d` 는 **레벨이 바뀌어도 안 내려가는 상주 자원**이다.
반면 한글 폰트(`boulderK16`)는 `frontend.p3d`·`ingame.p3d` 에 들어 있는 **레벨 자원**이다.
케이브는 영문 폰트 객체의 꼬리 6워드를 한글 폰트의 것으로 바꿔치기하므로,
`backend` 슬롯은 «레벨 자원의 글리프 배열»을 가리키게 된다.

미션 중 불러오기를 하면 레벨 자원이 먼저 해제된다. 그런데 소멸자 훅(`0x8023D5E4`)은
«영문 폰트가 해제될 때» 되돌리도록 돼 있다 — `backend` 의 영문 폰트는 «해제되지 않으므로»
되돌릴 기회가 영영 오지 않는다. 결국 **이미 풀린 배열을 계속 가리킨 채** 글자를 그리려다 멈춘다.

bootup 폰트(`boulder_16`·`Tt2001m__14`)는 이 문제가 없다 — 이들도 상주지만,
쓰이는 화면(프런트엔드·프롬프트)이 «레벨 자원이 살아 있는 동안»에만 그려지기 때문이다.
로딩 화면은 정반대로 «레벨 자원이 오르내리는 바로 그 순간»에 그려진다.

### 결론

로딩 화면 「로딩 중」은 `backend.p3d` 에 **이미 구워져 있는 한글 5자**(`데딩로모중`)로 충분하다.
신문 헤드라인 한글화는 이 길로는 안 된다.

⭕ 굳이 하려면 — 소멸자 훅이 «한글 폰트가 해제될 때도» 모든 슬롯을 되돌리도록 고쳐야 한다
   (지금은 해제되는 객체가 «슬롯에 등록된 영문 폰트»일 때만 되돌린다).
   훅 자리 `0x8023D5E4` 에서 r26 이 해제 대상이고, `KF`(0x80004D88)가 한글 폰트다.
   ⚠️ 그래도 «되돌린 뒤 다시 올라온 한글 폰트»에 재부착하는 문제가 남는다.

★ 도구 `tools/newshook.py` 는 지우지 않고 남겼다 — 훅 자리(`0x800B8C38`, r31=레벨 0~6),
  색인 배치(`812 + 레벨×4`), 글자칸 넓히기(`--widen`)는 다시 볼 때 그대로 쓸 수 있다.
  단 **그 케이브만으로는 안 되고 위 폰트 문제가 먼저 풀려야 한다.**
