# ISO 여유 공간과 코드 케이브 — ✅ **둘 다 해결**

세션 2 · 2026-09-08. 「케이브와 슬롯을 못 찾으면 전부 헛수고」라 먼저 판정했다.

## 1. ★★★ ISO 안에 525 MB 의 미사용 영역이 있다

```
디스크 1,459,978,240 B (1392.3 MB) · 파일 1,921개 합계 905,162,621 B (863.2 MB)
DOL  0x0001EC00 ~ 0x003F2040 (0x3D3440)
FST  0x003F2100 ~ 0x003FD32C (45,612 B)   ← DOL 바로 뒤. DOL 제자리 확장 불가(여유 0xC0)
파일 0x00400000 ~ 0x0052130C     (1.2 MB)
★★★ 0x0052130C ~ 0x2123D838     550,618,412 B (525.1 MB)  ← 미사용
파일 0x2123D838 ~ 0x57057FEC     (863 MB)
끝    ~0x57057FFC (뒤 20 B)
```

⚠️ 이 구멍은 **0 이 아니라 «난수 패딩»** 이다(표본 60곳 전부 고엔트로피).
게임큐브 디스크가 미사용 영역을 채우는 방식이며 **FST 어디서도 참조하지 않는다.**
→ 「0 인지」로 빈 공간을 판정하면 안 된다. **FST 커버리지로 판정해야 한다.**

## 2. 코드 케이브 — DOL 을 구멍으로 옮긴다

- DOL 안에는 쓸 만한 패딩이 없다(`text1` 에 48 B 이상 0 구간 **0개**).
  `text0`(0x80003100~0x80005620)에는 0 구간이 많지만 예외 벡터 영역이라 위험하다.
- DOL 헤더의 섹션 슬롯: **text 2~6 (5개) · data 8~10 (3개) 가 비어 있다.**
- 따라서 **DOL 전체를 구멍에 복사하고 새 text 섹션을 덧붙인 뒤,
  디스크 헤더 `0x420` 의 DOL 오프셋만 갱신**하면 된다. FST 는 건드리지 않는다.

## 3. 커진 파일 — 구멍에 놓고 FST 항목만 고친다

`srr2.p3d`(텍스트 바이블)가 커져도, 폰트 아틀라스가 커져도 마찬가지다.
**ISO 전체 재패킹이 필요 없다.**

```
FST 항목 12 B = [0]종류 · [1..3]이름오프셋 · [4..7]파일오프셋(BE) · [8..11]크기(BE)
```

★ 이로써 초기 조사(`docs/01` §6-6)부터 미해결이던
**「GC 는 파일 크기 변경이 가능한가」가 해결**됐다. 자막뿐 아니라 한글화 본편에도 그대로 적용된다.

## 4. 남은 확인

- 실기/돌핀이 «옮긴 DOL»을 정상으로 읽는지 (헤더 0x420 만 고치면 되는지) — 미검증
- 구멍에 놓은 파일을 게임이 정상으로 읽는지 — 미검증
  둘 다 작은 실험으로 확인 가능(예: 파일 하나를 구멍으로 옮기고 FST 를 고쳐 본다)

---

## 5. ✅ 실증 — 파일을 구멍으로 옮기고 FST 항목만 고쳤더니 «읽힌다»

`srr2.p3d`(646,016 B)를 `0x02360DCEC` → **`0x000528000`**(구멍)으로 복사하고
FST 항목의 오프셋만 갱신. 새 사본의 표식을 `PATCH TEST WORKS!` → `MOVED FILE OK!!!!` 로 바꿔
어느 사본을 읽는지 구분할 수 있게 했다.

→ 화면에 **`MOVED FILE OK!!!!`** 가 떴다. **ISO 전체 재패킹 없이 파일 이전·확장이 된다.**

도구 `tools/isofile.py` (`--list` / `--free` / `--move` / `--replace`).
⚠️ Git Bash 에서는 `MSYS_NO_PATHCONV=1` 필수(`/art/...` 인수가 윈도 경로로 바뀐다).

### 이로써 열린 것

- 자막용 «긴 슬롯» — 텍스트 바이블을 키워 구멍에 배치
- 한글화 본편의 텍스트 바이블 확장
- 한글 폰트 아틀라스 확대(256×128 → 1024×1024)
- 그 밖에 크기가 커지는 모든 파일

## 6. ✅ 실증 — DOL 을 구멍으로 옮겨도 정상 부팅

DOL(0x3D3440 B)을 `0x0001EC00` → **`0x00600000`** 으로 복사하고
디스크 헤더 `0x420` 의 DOL 오프셋만 갱신 → **게임이 정상으로 돌았다.**

★ **코드 케이브 확보.** 이제 DOL 뒤에 새 text 섹션을 덧붙일 수 있다
(헤더 슬롯 text 2~6 · data 8~10 이 비어 있다).
FST 는 손대지 않았고, 아플로더도 문제 없었다.

### 남은 것은 «만들기»뿐

```
✅ 자막 표시 방식      두 줄 · 깨끗한 화면까지 실증
✅ 대사 식별          이벤트표 0x80379C08 · 캐릭터표 0x80379F50 · 처리함수 0x80131D44
✅ 파일 크기 변경      FST 항목만 수정 (여유 525 MB)
✅ 코드 케이브        DOL 이전 (헤더 0x420)
⏳ 훅 작성            대사 재생 시 자막 슬롯에 UTF-16 memcpy
⏳ 텍스트 바이블 재구성  자막 619줄 + 긴 슬롯
⏳ 번역 619줄         영문 대본 2/3 확보 (나머지는 음성 청취)
```

## 7. ✅ 실증 — 「자막이 음성에 맞춰 순서대로」 넘어간다

호스트에서 훅을 흉내 내 시험했다(`tools/syncdemo.py`).

```
감시   0x8044A7C8   (0x80000000 유휴 ↔ 0x803039A8 재생)
동작   유휴→재생 전환마다 다음 대사 줄을 자막 슬롯 두 곳에 써 넣는다
슬롯   L1 = BASE+0x9EAE (Accept 요소가 읽음) · L2 = BASE+0x5EE0 (Cancel 요소)
       BASE = 0x808BC919
```

**결과 = 개념 실증 성공.** 대사가 바뀔 때 자막도 «순서대로» 넘어갔다.

### ⛔ 다만 이 감시 주소는 배포용이 못 된다

60초에 **110회 전환**했다. 대사는 4줄뿐이었으니 나머지는 발소리·효과음 등
**모든 사운드**가 같은 워드를 토글한 것이다. 그래서 화면에서 자막이
「순간적으로 마구 바뀌는」 깜빡임이 생긴다.

로그를 보면 진짜 대사만 길다 — 3.7s · 3.5s · 6.0s. 나머지는 대부분 0.1초 미만.
즉 **지속시간 필터(≥1.5s)로 거를 수는 있지만 어림짐작이라 배포에 못 쓴다.**

★ 결론: **감시(polling)가 아니라 «대사 처리 함수 자체»에 훅을 걸어야 한다.**
`0x80131D44` 는 대사일 때만 불리므로 깜빡임이 원리적으로 생기지 않고,
이벤트 ID·화자·미션이 레지스터에 그대로 들어 있다.
→ 다음 작업은 케이브에 PPC 훅을 심고 «어느 대사에 어떤 값이 오는가» 표를 만드는 것.
