# PoC — 텍스트 바이블 교체가 화면에 반영되는가  ✅ **성공**

세션 2 · 2026-09-08 · 돌핀 실기 확인

## 결과

`srr2.p3d` 의 영문(`E`) 문자열 두 개를 **같은 글자 수**로 바꿔 ISO 에 제자리 기록했더니
화면에 그대로 나왔다.

| 위치 | 원래 | 바꾼 값 |
|---|---|---|
| 튜토리얼 상자 첫 줄 (`00218D15`) | `USE [ OR + TO MOVE AROUND` | `TEXT BIBLE PATCH OK !!!!!` |
| 아래 안내 (`0025A620`) | `Disable Tutorials` | `PATCH TEST WORKS!` |

```
ISO 0x02362640C  (srr2.p3d + 0x18720)
ISO 0x02362A0CE  (srr2.p3d + 0x1C3E2)
srr2.p3d 는 ISO 0x02360DCEC · 646,016 B
```

## 이걸로 확정된 것

1. ★★★ **텍스트 바이블을 고치면 화면 글자가 바뀐다** — 한글화 본편의 핵심 전제.
2. ★★ **영문 슬롯 `E` 하나만 고쳐도 된다.** 다른 언어 슬롯 4개(FGIS)는 안 건드렸는데 반영됐다.
3. ★ 게임은 `srr2.p3d` 를 **그대로** 읽는다(`.rcf` 안의 사본 같은 우회 경로가 없다).
4. ★ 버튼 아이콘 자리 `[`·`+` 는 **치환 표식이 맞다** — 글자로 바꾸니 아이콘이 사라졌다.
5. ISO 안 파일을 «크기 불변»으로 제자리 수정하면 FST·재빌드가 필요 없다.

도구 `tools/txtpatch.py` (`--find` / `--set`, 길이가 다르면 거부).

## 남은 것 (본 빌드에서 풀어야)

- 길이가 «달라지는» 교체 → 오프셋 표 `off[n]` · `blen` · 청크 크기 재작성.
  그러면 `srr2.p3d` 크기가 변하므로 **FST 재작성 또는 여유 공간 배치**가 필요하다.
- 한글 글리프(`docs/02_폰트.md`) — 지금 폰트엔 한글이 없으므로 넣으면 □ 로 나온다.

# ⛔ 실패한 PoC — 「문자열 하나로 함수를 특정」한 오류

같은 세션에서 **먼저 시도했다가 실패**한 것을 기록해 둔다.

`'No Valid Text'` 문자열을 참조하는 코드 `0x80214A6C` 를 단서로, 그 함수 `0x80214A10` 을
「화면 텍스트 내용의 목구멍」이라 보고 분기 하나를 `beq`→`b` 로 바꿨다.
→ **화면이 전혀 안 변했다.**

원인: 그 함수는 **호출자가 0곳**이었다(가상함수로만 불리거나 죽은 코드).
문자열 하나가 「그럴듯한 함수」 안에 있다고 그게 실제 경로라는 뜻이 아니다.
→ [[feedback_check_callers_before_trusting_string_anchor]]

★ 다만 그 시도에서 건진 것 —
- 화면 문자열은 **UTF-16**이다(`0x8021BD2C` 가 `lhzx` 로 읽는다).
- 문자열 API: 생성 `0x8021B734` · char*대입 `0x8021BC64`(ASCII→UTF-16 승격) ·
  UTF-16 대입 `0x8021BD2C` · 복사 `0x8021B7F4`.
- ISO 안 DOL 을 제자리 수정 → 돌핀 실행까지 **왕복이 성립**한다(`tools/dolpatch.py`).
- ★ 시험이 «유효»했는지 먼저 확인했다 — 같은 폴더에 `.rvz` 가 없고 패치 시각(13:27)이
  실행(13:30)보다 앞섬. 무효 회차를 정상으로 오독하는 함정을 피했다.

# PoC-C — 텍스트 바이블 블롭 «실시간 쓰기»  ✅ **성공**

세션 2 · 2026-09-08 · 돌핀 실행 중 메모리 직독/직쓰기 (`gc-modern-controls/tools/dolmem.py`)

## 확인된 구조

```
srr2.p3d 의 «문자열 영역»(영문 E, 127,240 B)이 RAM 에 통째로 상주한다.
   블롭 시작 = 0x808BC919   ← 두 표식으로 이중 확인
      'PATCH TEST WORKS!'        파일 p3d+0x1C3E2 → RAM 0x808D8CFB
      'TEXT BIBLE PATCH OK !!!!!' 파일 p3d+0x18720 → RAM 0x808D5039
   두 경우 모두 (RAM − 파일오프) = 0x808BC919 로 일치.
★ 블롭 시작이 «홀수»다. 즉 UTF-16 문자열이 2바이트 정렬이 아니다(PPC 는 비정렬 로드 허용).
★ 화면 텍스트의 «복사본»이 RAM 에 없다 — 짝수정렬 UTF-16 문자열을 전수 조사해도
  텍스트바이블 원문과 일치하는 것이 0개. 렌더러가 블롭을 «직접» 읽는다.
```

## 실험

일시정지 화면이 뜬 상태에서 블롭에 직접 써 넣었다(같은 글자 수).

| RAM | 원래 | 쓴 값 | 화면 |
|---|---|---|---|
| `0x808BFF5B` | `PAUSE MENU` | `RAM WRITE!` | ✅ 바뀜 |
| `0x808C73BB` | `OPTIONS` | `WRITTEN` | ✅ 바뀜 |
| `0x808D2531` | `RESUME GAME` | `LIVE RAM OK` | (그 화면에 없음) |
| `0x808D2923` | `RESTART MISSION` | `HOOK TEST WORKS` | (그 화면에 없음) |
| `0x808DBDA5` | `MAP` | `ZZZ` | (그 화면에 없음) |

## ★★★ 이것이 자막 설계를 바꾼다

```
① 텍스트 바이블에 «자막 전용 칸»을 만든다(충분히 긴 자리)
② 화면에 그 칸을 쓰는 텍스트 요소를 하나 둔다
③ 훅이 대사 재생 시점에 그 칸에 UTF-16 을 memcpy 한다      ← 실증 완료
```

③ 은 문자열 객체 생성도, `radString` API 호출도, `vtbl[0x138]` 가로채기도 필요 없다.
**정해진 주소에 바이트를 쓰기만 하면 된다.** 가장 어려울 줄 알았던 부분이 가장 쉬워졌다.

⚠️ 블롭 주소 `0x808BC919` 는 이 실행에서 관측한 값이다. **로드 위치가 매번 같은지 확인해야 한다.**
   다르면 훅이 런타임에 블롭 주소를 얻어야 한다(텍스트바이블 객체 포인터를 통해).

## 남은 관문 — ② 화면 요소 하나

`ingame.p3d` 에 텍스트 요소(`0x00018007`)를 추가하려면 파일 크기가 변하고 FST 재작성이 필요하다.
대안: HUD 에 이미 있는 요소(예: 화면 아래 목표 바)를 대사 중에만 자막으로 쓰고 끝나면 되돌린다.

# PoC-D — 대화 화면(레터박스)에서도 블롭 쓰기가 먹히는가  ✅ **성공**

세션 2 · 2026-09-08 · 돌핀 «에뮬레이션 일시정지» 상태에서 RAM 직쓰기

## 상황

마지와의 미션 시작 대화 = 위아래 검은 레터박스 + **하단 바에 `Ⓐ Start Mission` / `Ⓑ Cancel`**.
이 하단 바가 자막이 놓일 자리다.

## 결과

| 문자열 | RAM | 블롭 안? | 화면 |
|---|---|---|---|
| `Cancel` → `Sub2!!` | `0x808C27F9` (블롭+0x5EE0) | ✅ | ✅ **바뀜** |
| `Start Mission` → `SUBTITLE LINE` | `0x80651051` | ⛔ 블롭 밖 | ⛔ 안 바뀜 |

★★★ **대화 화면의 하단 바에도 «블롭 기반» 텍스트 칸이 있다.**
즉 대사가 흐르는 동안 자막을 띄울 자리가 실재하며, 우리가 몰 수 있다.

⚠️ `Start Mission` 은 블롭 밖 사본(`0x80651051`)에서 온다 — 같은 화면 안에서도
**칸마다 출처가 다를 수 있다.** 자막 칸을 고를 때 「그 요소가 실제로 읽는 칸」을 정확히 짚어야 한다.
⚠️ 같은 문구가 블롭 안에 **여러 칸** 있다(`TALK TO MARGE` 가 두 곳).

## ✅ 자막 실현 가능성 — 네 관문 전부 통과

| | |
|---|---|
| ① 대사 식별 | 이벤트표 `0x80379C08`(45) · 캐릭터표 `0x80379F50`(58) · 처리함수 `0x80131D44` |
| ② 자막 문자열 저장 | 텍스트 바이블(UTF-16) · 619줄 추가 가능 |
| ③ 화면 반영 | 블롭 `0x808BC919`(재시작 후에도 동일) 에 쓰면 즉시 반영 |
| ④ 대화 중 표시 자리 | 레터박스 하단 바 — 블롭 기반 확인 |

## 남은 것은 «구현»

1. **충분히 긴 자막 칸 확보** — `Cancel` 칸은 6자라 너무 짧다.
   바이블을 재배치해 긴 슬롯을 만들거나(→ 크기 변경 → FST 재작성),
   기존의 긴 항목(미션 지시문 등) 중 그 요소가 읽는 것을 골라 빌린다.
2. **코드 케이브** — DOL 안에 훅 코드를 심을 자리(text 섹션이 파일에서 빈틈없이 붙어 있어
   기존 패딩을 찾거나 DOL 을 옮겨 새 섹션을 붙여야 한다).
3. **훅 작성** — 대사 재생 시점에 (이벤트ID·화자·미션) → 자막 문자열을 골라
   자막 칸에 UTF-16 memcpy. 블롭 주소가 고정이라 하드코딩 가능.
4. 자막 표시 시간 = 이벤트표의 `timeMs` 를 기본값으로.

# PoC-E — 자막 «완전 시연»  ✅✅ **성공**

세션 2 · 2026-09-08 · 대화 레터박스 바에 65자 자막을 한 줄로 표시

## 자막 자리의 정체 — `LetterBoxButtons.pag`

`ingame.p3d` 안. **대화(레터박스) 중 하단 바 전용 페이지**다.

```
0x00018002 페이지 'LetterBoxButtons.pag'          ISO 0x022DD9370
  0x00018100 이미지참조 'accept' · 'back'
  0x00018105 바이블참조 'srr2'      0x00018104 폰트참조 'font0_16'
  0x00018003 레이어 'Overlay'
    0x00018004 그룹 'Skip'
      0x00018004 그룹 'SkipLabel'
        0x00018007 텍스트요소 'Skip'   키=SKIP            필드 ISO 0x022DD94CB
      0x00018004 그룹 'BackLabel'
        0x00018007 텍스트요소 'Cancel' 키=CANCEL          필드 ISO 0x022DD959F
      0x00018004 그룹 'AcceptLabel'
        0x00018007 텍스트요소 'Accept' 키=ACCEPT_MISSION  필드 ISO 0x022DD9677
```

⛔ 함정: 같은 이름의 `Cancel.pag`·`Accept.pag` 가 따로 있는데 **그건 이 바가 아니다.**
처음에 `Cancel.pag` 를 고쳤다가 화면이 안 바뀌어 한 회차를 날렸다.
★ 요소를 찾을 땐 «이름»이 아니라 **키(`0x0001800B`)로 전 파일을 훑어** 후보를 좁혀야 한다.

## 텍스트 요소 필드 (0x00018007, 이름 뒤 10×u32 LE) — ★실측 확정

```
[0]=17(0x11) 종류?
[1]=x        왼쪽 기준
[2]=y        ★ «화면 아래»에서 잰 값 — 크면 위로 (높이가 아니다)
[3]=폭       ★ 자르지도 줄바꿈하지도 «않는다». 정렬 계산에만 쓰인다
[4]=글자 크기 (바 라벨 18 · Message 16 · Credits 15)
[5]=정렬     ★ 0 = 왼쪽 · 4 = 가운데
[6]=2  [7]=0xFFFFFFFF  [8][9]=0
```

실험 이력 —
| 바꾼 값 | 화면 |
|---|---|
| `Accept` `[1]` 135→60 | 글자가 왼쪽으로 이동 ⇒ `[1]`=x |
| `[5]` 0→4 | 가운데 정렬 ⇒ `[5]`=정렬 |
| `[2]` 40→20 | 아래로 이동 |
| `[2]` 20→80 | 위로 이동 ⇒ `[2]`= 아래 기준 y |
| `[3]` 100→520 + 65자 | **자르지 않고 넘쳐 흐름** ⇒ 폭은 상한이 아니다 |

⛔ **`\` 는 이 요소에서 줄바꿈이 아니다** — 글자 그대로 표시된다.
(초기 조사 `docs/01` 의 「`\` 가 줄바꿈」은 튜토리얼 상자를 보고 한 «추정»이었다. 요소마다 다르다.)

## ★ 조판 사양 (4:3 기준 실측)

```
한 줄 상한   약 61자 (글자 크기 18, 가변폭이라 문장마다 다름)
             65자를 넣으니 양쪽 2자씩 원본 프레임 밖으로 넘쳤다
```
⚠️ **와이드 패치 상태의 화면으로 판정하면 안 된다.** 원본 4:3 프레임(좌우 검은 기둥 안쪽)이 기준.
   이 함정에 한 번 걸려 「65자가 한 줄에 들어간다」고 잘못 결론냈다.

## ★ 두 줄 자막은 «요소 두 개»로

`LetterBoxButtons.pag` 에 텍스트 요소가 이미 3개 있다. 둘을 자막 1·2줄로 돌린다.

```
Accept (ISO 0x022DD9677) → 1줄   [1]=60 [2]=45 [3]=520 [5]=4
Skip   (ISO 0x022DD94CB) → 2줄   [1]=60 [2]=25 [3]=520 [5]=4
Cancel (ISO 0x022DD959F) → 미사용(화면 밖으로)
```
전부 **크기 불변 제자리 수정** — FST 재작성 불필요.

## 시연

1. ISO 에서 `Accept` 요소를 `[1]=60`·`[3]=520` 으로 **제자리 수정**(크기 불변) → 재로딩
2. 실행 중 RAM 의 블롭 슬롯(`블롭+0x9EAE`, `Start Mission` 자리)에 65자 UTF-16 을 써 넣음

```
Homie, somebody ate every dessert in the house. Go get ice cream!
```

→ 레터박스 바에 표시됐다. **다만 「한 줄에 들어갔다」는 잘못된 판정이었다** —
   시험 화면이 «와이드 패치» 상태여서 원본 4:3 프레임 밖까지 그려진 것이고,
   `ice cream!` 부분은 원본 화면에서는 **잘려 안 보인다.**
★ 실제로 드러난 것: **`[3]`(폭)은 자르지도 줄바꿈하지도 않는다.** 글자가 그대로 넘쳐 흐른다.
   → 자막 한 줄 길이를 «글자 수»로 직접 제한하거나, 줄바꿈 모드를 찾아야 한다.
   후보: `[5]` (바 라벨은 0, 여러 줄인 `Message`·`Credits` 는 4).

## ✅ 자막에 필요한 조각 전부 실증

| | 방법 | 근거 |
|---|---|---|
| ① 대사 식별 | 이벤트표 `0x80379C08`(45) · 캐릭터표 `0x80379F50`(58) · 처리함수 `0x80131D44` | 정적 RE |
| ② 문자열 저장 | 텍스트 바이블(UTF-16) | PoC-B |
| ③ 화면 반영 | 블롭 `0x808BC919` 쓰기(주소 고정) | PoC-C |
| ④ 표시 자리 | `LetterBoxButtons.pag` | PoC-D |
| ⑤ 위치·폭 제어 | 요소 `[1]`=x·`[3]`=폭, 제자리 수정 | PoC-E |
| ⑥ 한 줄 길이 한계 | ⛔ **미확정** — 폭은 자르지 않는다. 4:3 기준 재측정 필요 | PoC-E 정정 |

## 남은 구현

1. **자막 전용 요소 정하기** — `Skip`(대화 중 미사용, 가운데)이 유력.
   대사 중 `Accept`/`Cancel` 텍스트와 버튼 아이콘(`0x00018006`)을 숨기거나 자막을 다른 줄에.
2. **긴 슬롯 확보** — 자막 문자열이 들어갈 충분히 긴 바이블 항목.
   (지금 실험은 뒤 항목을 덮어썼다. 훅이 저장·복원하거나, 바이블 재배치로 전용 칸을 만든다.)
3. **코드 케이브** — DOL 안 훅 자리.
4. **훅** — 대사 재생 시 (이벤트ID·화자·미션) → 자막 문자열을 슬롯에 UTF-16 memcpy.
   표시 시간은 이벤트표 `timeMs`.
5. ⛔ **동영상(Bink `.rmv` 12편)에는 자막을 못 넣는다** — UI 가 없다. 인게임 대화 619줄만 대상.

# PoC-F — 두 줄 자막  ✅✅ **성공 (자막 표시 방식 확정)**

세션 2 · 2026-09-08

## 배치

`ingame.p3d` / `LetterBoxButtons.pag` 의 텍스트 요소 두 개를 자막 1·2줄로 재배치(제자리 수정).

| 요소 | ISO | 원래 | 자막용 |
|---|---|---|---|
| `Accept` (키 `ACCEPT_MISSION`) | `0x022DD9677` | 17 135 40 100 18 0 | **17 60 45 520 18 4** |
| `Cancel` (키 `CANCEL`) | `0x022DD959F` | 17 455 40 100 18 0 | **17 60 22 520 18 4** |
| `Skip` (키 `SKIP`) | `0x022DD94CB` | 17 315 40 100 18 0 | (이 화면에선 안 그려짐) |

실행 중 블롭에 각 줄을 써 넣음 — 1줄 `블롭+0x9EAE`, 2줄 `블롭+0x5EE0`.

```
Homie, somebody ate every dessert in the house.      47자   y=45
I need you to get some of that ice cream.            41자   y=22
```

→ **두 줄이 가운데 정렬로 나란히, 원본 4:3 프레임 안에 온전히 표시.**

## ★ 조판 사양 (확정)

```
한 줄 안전선  약 55자 · 최대 약 60자   (글자 크기 [4]=18, 가변폭)
   47자 = 바 폭의 약 80%  ·  65자 = 양쪽 2자씩 넘침
줄 수         2줄 (요소 두 개). 필요하면 세 번째 요소로 3줄도 가능
줄 간격       y 45 / 22  (약 23)
정렬          [5]=4 가운데 · 상자 [1]=60 [3]=520 → 중앙이 화면 정중앙(320)
```

## 남은 손질

- Ⓐ·Ⓑ 버튼 «아이콘»은 형제 청크 `0x00018006` 에 따로 있다(좌표 형식 동일).
  자막 중에는 화면 밖으로 치워야 한다.
- 실제 구현에선 대화 중 그려지는 요소가 무엇인지 장면별로 확인해 자막 요소를 고른다
  (`Skip` 은 스킵 가능한 컷신에서만 나온다).
