# 심슨 히트 앤 런 — 「인게임 자막 없음」 판정과 **무기한 보류**

세션 2 · 2026-09-08 · **사용자 지시로 무기한 보류.** 따로 얘기가 있을 때까지 착수하지 않는다.

## 1. ⛔ 이 게임에는 «자막 시스템»이 없다

사용자가 실기에서 「인게임 대부분의 대사에 자막이 없다」를 관측했고, 데이터로 확인했다.

- UI 정의(`0x0001800B`)에서 **키 이름 1,232개 전량**을 훑었다 —
  `SUB` · `TEXT` · `CAPTION` · `DIALOG` · `CONV` · `LINE` · `SPEECH` 계열이 **0개**.
- 텍스트 바이블 1,629 항목에 `subtitle`·`caption` 문자열이 **없다**.
- 옵션이 꺼져 있는 게 아니라 **기능 자체가 없다.**

## 2. ★ 세션 1 기록의 오류를 정정한다

`docs/01_초기조사.md` §2 에서 `0x00227AFC "Oh don't worry about it…"` 류를
「**대사 자막**」으로 적었는데 **틀렸다.** 이들은 **수집 카드의 인용문**이다
(키 이름이 `CARD_TITLE_00`~ 꼴, 141개). 인용부호로 시작하는 대사체라서 착각했다.

★ 교훈: **문자열이 «대사처럼 보인다»고 자막이라고 단정하지 말 것.**
키 «이름»(`0x0001800B`)까지 확인하면 바로 갈렸다. → [[feedback_dialogue_looking_string_is_not_subtitle]]

## 3. 실제 번역 대상 분포 (전량 분류)

| 분류 | 항목 | 문자수 | 비중 |
|---|---:|---:|---:|
| 미션 지시문(대문자) | 442 | 15,895 | 25.6% |
| 기타 안내문 | 236 | 19,404 | 31.3% |
| 세이브/메모리카드 | 122 | 9,615 | 15.5% |
| 카드 인용문(대사체) | 99 | 6,786 | 10.9% |
| UI 짧은 항목 | 535 | 5,818 | 9.4% |
| 힌트 | 88 | 4,364 | 7.0% |
| 빈칸·자리표시 | 107 | 109 | — |
| **합계** | **1,629** | **61,991** | |

→ 미션·안내·힌트·UI = **약 78%(48,000자)** 가 «플레이에 직접 필요한 텍스트».
   이 게임은 미션 목표가 화면 글자로만 주어지므로 **한글화하면 플레이는 온전히 된다.**
   잃는 것은 컷신·주변 대사의 맛이다(원판부터 자막이 없다).

## 4. 재개할 때의 선택지

- **㉮ 그대로 진행** — 있는 텍스트 전량 번역. 배포 시 「인게임 음성 대사는 원판부터 자막이 없다」를 명시.
- ㉯ 자막 시스템을 «새로» 만든다 — ⛔ 대사 «원문 텍스트가 게임 안에 없다**(`dialog.rcf` 159 MB 는 음성뿐).
  전사부터 해야 하고 엔진 개조 규모가 본편 번역보다 크다. 사실상 별개 프로젝트.
- ㉰ 접는다.

조사 자체는 ㉮ 를 곧바로 시작할 수 있는 상태다 —
텍스트(UTF-16LE)·폰트(인라인 p3d) 둘 다 해독을 마쳤다. 남은 관문은
**ISO 재빌드에서 파일 크기 변경이 되는가** 하나다(`docs/02` §6).

# 부록 — 「자막을 만든다면」 (2026-09-08 추가 조사)

사용자가 GameFAQs 대본을 가져왔고, 그걸 계기로 **자막 시스템의 실현 가능성**을 재 봤다.
결론: **자료 쪽은 사실상 풀렸고, 남은 진짜 관문은 «엔진 훅» 하나다.**

## A. 대사는 «이름»으로 관리된다 — 목록화가 된다

`dialog.rcf`(159 MB) 는 `RADCORE CEMENT LIBRARY` 아카이브이고, **3,885 항목이 평문 이름**이다.

| 접두 | 수 | 정체 |
|---|---:|---|
| `w_` | 1,280 | NPC 응답 (doorbell · idlereply · ridereply · foodreply) |
| `d_` | 874 | 운전 중 대사 (bcrash · mcrash · damage · arrive · burn) |
| **`c_`** | **1,482** | 컷신·대화. 그중 **미션 태그가 붙은 619줄**이 스토리 대사 |
| `p_` | 807 | 보행자 반응 (hitbyc · hitbyw · nhitbyc) |
| `v_` | 99 | 차량·피해자 |

**대사 이름 구조**

```
c_ project _1_ convinit _ mrg _ l1m1 .rsd
   └주제    └순서 └대화형식  └화자  └미션
```

미션 태그 `l1m1`~`l7r3` **71종**(레벨 7 × 미션 7 + 레이스 3).
화자는 3글자 코드(`hom` `mrg` `lis` `brt` `apu` `fla` `bur` `smi` `len` `brn` `crl` …).

산출물: `work/dialog_lines.tsv`(619줄, 필드 분해) · `work/dialog_names.txt`(3,885줄 전량)
도구: `tools/rcfnames.py`

## B. 미션 스크립트가 대화를 «선언»한다

`.mfk` 는 평문이고 명령 어휘 222종이 있다. 관련된 것:

```
SetDialogueInfo("homer","marge","project",0)   ← 화자 / 상대 / ★주제 / 플래그   (138곳)
SetConversationCam(0,"pc_far","sr1")           ← 줄마다 카메라 = 줄 수·순서     (399곳)
SetStageMessageIndex(145)                      ← ★ 텍스트 바이블 «색인»으로 화면 메시지 (495곳)
SetCompletionDialog("mower")                   ← 완료 대화                      (45곳)
```

★★★ **`SetDialogueInfo` 의 셋째 인수가 대사 이름의 «주제» 와 같다.**
→ 어느 미션에 어떤 대화가 몇 줄 있고 누가 먼저 말하는지를 **게임 파일만으로** 표로 만들 수 있다.

★★ `SetStageMessageIndex(N)` 은 **글자 찍는 기계가 이미 있고 색인으로 구동된다**는 증거다.

## C. 엔진이 이름을 «런타임에 조립»한다

DOL `0x395770` 부근에 토큰 표가 있다:

```
convinit · noboxconv · tutorial · Activate · Springboard · Doorbell · Ridereply · Greeting · Idlereply · Foodreply
```

정확히 대사 파일명의 둘째 토큰들이다.
→ **재생 시점에 어떤 대사인지 엔진이 알고 있다.** 자막의 최대 난제(「지금 뭐가 나오는지 모른다」)가 없다.

## D. 영문 대본 — 약 2/3 커버

`work/script_gamefaqs_spacepirate.txt` (GameFAQs FAQ #30912, SpacePirate, 65,402 B)
⚠️ GameFAQs·DonutTeam·TCRF·Fandom 은 봇 차단(403/402)이라 사용자가 저장해 준 사본이다.

```

Homer 74 · Bart 74 · Lisa 40 · Marge 37 · Apu 35 · Snake 14 · Wiggum 12 …
```

**정렬 시험(실제로 붙여 봤다)** — 게임 `l1m1` 의 `project` 대화 = `mrg → hom → mrg → hom` 4줄.
대본 Mission 2 의 「Homie, Lisa left for school without her science project…」 이하 4줄과
**화자 순서·줄 수가 정확히 일치**. 옆의 `bladder` 도 대본의 「where's the **gall bladder**」와 주제어가 맞는다.

⚠️ 한계 —
- 게임 `bladder` 6줄 vs 대본 4줄 → **합치거나 빠진 곳이 있다**(작성자도 「다 알아듣진 못했다」고 적었다).
- **미션 번호가 한 칸 어긋난다**(대본 Mission 2 = 게임 `l1m1`). 대본은 플레이 순서, 게임은 내부 번호.
- 대본 432줄 vs 게임 619줄 → **약 190줄이 대본에 없다.** 음성을 듣고 채워야 한다.
- 다른 출처(DonutTeam 전사 문서)는 **게임 내부 이름 기준**일 가능성이 있어 확보하면 정렬이 통째로 사라진다.

# 부록 2 — DOL 역공학: 대사 이벤트 계통 (2026-09-08)

「토큰 표를 쓰는 코드를 찾아라」에서 시작해 **대사 계통 전체를 짚었다.**
도구 `tools/doltables.py`(표 덤프) · 분석 스크립트는 임시로만 씀.

## 0. DOL 기본

```
DOL   ISO 0x1EC00 ~ 0x3F2040 (0x3D3440 B) · 진입점 0x80005304
text0 VA 0x80003100 (0x2520)   text1 VA 0x80005880 (0x331DE0)
data  VA 0x80005620 / 0x80005760 / 0x80337660 / 0x803377C0 / 0x80337800 /
      0x80343DE0 / 0x8046BE20 / 0x80477920
r13 (SDA base) = 0x80473E20     ← 진입점의 `lis r13,-0x7fb9 / ori r13,r13,0x3e20`
BSS   0x803C8C20 (728,852 B)
```

## 1. ★ 대사 «이벤트 종류» 표 — VA 0x80379C08 · 45개

```c
struct EventType { const char* name; u32 zero; u32 id; u32 timeMs; };   // 0x10 B
EventType g_eventTypes[45] @ 0x80379C08;
u32       g_eventTypeCount @ 0x8046FAD8 (= r13-0x4348) = 45;
const EventType* GetEventType(int i) @ 0x80132C28;   // 범위 밖이면 NULL
int              GetEventTypeCount() @ 0x80132C4C;
```

`GetEventType` 실체:

```asm
lwz  r0, -0x4348(r13)   ; 개수
lis  r4, 0x8038
slwi r5, r3, 4          ; i × 0x10
addi r0, r4, -0x63F8    ; = 0x80379C08
add  r3, r0, r5
bltlr / li r3,0 / blr
```

주요 ID — `convinit=0x11F` · `noboxconv=0x124` · `tutorial=0xD4` · `Mfail=0x9B` ·
`Mvic=0xEF` · `Dcar=0xC2` · `Mstart=0x111` · `Activate=0xD2`.
`timeMs` 는 대개 2500, `Mfail/Mvic` 4000, `Dcar` 5000, `Activate` 250,
응답류(`Askride/Ridereply/Answer/Idlereply/Foodreply/Mstart`) 0.
**★ 자막 표시 시간의 기본값으로 쓸 수 있다.**

## 2. ★ 캐릭터 표 — VA 0x80379F50 · 항목 0x18 B · **58명**

★★★ **이 3글자 코드가 대사 파일명의 화자 토큰과 같다**(`C_accuse_2_convinit_Bur_L1M7`).

## 3. 대사 이벤트 처리 함수 — VA 0x80131D44 ~ 0x80132538

- 인수: `r30` = 이벤트 ID. `cmpwi r30, 0xC1/0xC2/0xE2/0x9B/0x11F/0x124/0x111/0xEA…` 로 분기.
- **`0x80132028` 근처가 대화형(convinit/noboxconv) 분기** — `cmpwi 0x11F` / `cmpwi 0x124`.
- `0x80132520  bl 0x80135308` = 재생/대기열 진입.
  인수 `r3=[r31+0xC]`, `r4=r20`(사운드 분류 색인), `r5=r23`.
  ⚠️ `r5` 는 **3D 좌표 버퍼**다(`0x801329D4` 가 오브젝트의 `+0x48/0x4C/0x50` 실수 3개를 복사).
  즉 이 인수에는 «이름»이 없다.
- `0x80132578` 등록 루프: `GetEventTypeCount()` → `GetEventType(i)` → `+8`(ID) 로
  리스너 등록. 마지막에 `0x121` 도 추가 등록.

## 4. ★★★ 이름 조립의 «부품»은 전부 SDA 상수에 있다

`r13-0x45xx ~ -0x41xx` 구간에 이벤트명 35종과 캐릭터 코드/긴이름 쌍이 나란히 있다.
`0x80131E98` 처럼 `addi r4, r13, -0x446C` 로 조각을 집어 `bl 0x80227024`(문자열 조립 함수)
로 넘긴다. **sprintf 서식이 아니라 «조각 결합»이라 서식 문자열 검색으로는 안 잡혔다.**

→ 즉 리소스 이름은 런타임에 «이벤트명 + 3글자 화자코드 (+ 미션태그)» 로 만들어지고,
그 결과가 `.spt` 의 `create daSoundResourceData named …` 이름과 1:1로 맞는다.

## 6. 남은 것 — 훅 지점 확정

지금까지로 **「재생 시점에 어떤 대사인지 알 수 있는가」는 «된다»로 판정**됐다.
남은 작업은 셋뿐이다.

1. **이름이 완성되는 정확한 명령**을 짚는다(`0x80227024` 계열 호출의 결과 버퍼).
   또는 더 간단히 «이벤트ID + 화자 인덱스 + 미션» 세 값을 잡아 오프라인 표로 찾는다.
2. **코드 케이브에 훅**을 심어 그 값으로 자막 문자열을 고른다.
3. **화면에 그리는 함수**를 찾아 호출한다(텍스트 바이블 색인 구동 경로가 이미 있다 —
   `SetStageMessageIndex` 가 그 증거. 다만 스테이지 단위라 그대로는 못 쓰고 하위 함수를 찾아야 한다).

⛔ 프로젝트는 여전히 **보류**다. 이 부록은 재개 시점의 출발선이다.
